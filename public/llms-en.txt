# Loom — Private Content Production Whitelist Platform

Loom is a 13-stage content production chain (CHAIN_13): it turns "product information → publishable content" into an orchestratable, auditable, quality-gated production line. AI drafts candidates only, human gates decide, `final_id` is the single publishable exit, and feedback flows back into the knowledge base.

## Core concepts

- **The 13-stage chain**: product intake → cold-start modeling (C1 five-signal) → field pool planning → atoms under fields → PWC condition packages → PWS freeze → platform adaptation → PCP platform package → CSP/CSTP/CEP bundles → compliance cleaning → final_id assembly → content generation → feedback loop.
- **The whitelist is a collision product**: usable condition packages produced by atoms colliding under a (product × purpose × platform × account) context — not a hand-written word list.
- **final_id**: the sum of six layer snapshots (PWS + PCP + CSP + CSTP + CEP + CCR), exiting through the single `E1.1 publishFCW`; assembled only when every guard passes, consumed read-only.
- **Quality is structural**: every stage ends in a human gate / guard / review; frozen PWS snapshots separate decisions from consumption.
- **Auditable and write-back**: Q1–Q72 decision log, writeAudit, single exit, feedback loop (KUP proposals → human gate → knowledge write-back).

## Key differentiators

- Unlike plain AIGC tools, generated content is a *candidate*, not the end; a human gate decides whether it may be used.
- Unlike word-list filtering, the whitelist is generated by contextual collisions and every atom traces back to a decision source.
- The content generation system only ever consumes frozen whitelists read-only; it never touches raw decision data.
